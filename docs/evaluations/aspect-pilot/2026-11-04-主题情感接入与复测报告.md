# 主题情感接入与真实模型复测记录
日期：2026年11月4日。编写与补标：Codex。原50条的用户意见：整体同意。独立人工复标：尚未完成。

## 平台变更
客户痛点页默认进入主题情感工作台：9组19具体标签，每条评论可有多个标签，每个标签独立正面/负面/中性，显示原文片段及判断情境。不设“其他”，目录未覆盖时允许空标注并显示覆盖说明。原短语规则工作台作为历史对照入口保留，新旧纠错分开。
当前内置76条模拟评论由Codex整理，其中50条72个条目经用户整体认可；另外26条补查生成26个条目，尚未经用户确认。合计98个条目，70条评论有标签。r066、r068、r070、r073、r074、r076暂无对应标签：一般性价比、补水操作/一般维护、整体满意、未指定部件的耐用性、整体可靠性与成本、陶瓷易崩缺均不能硬套已有分类。其他部分覆盖评论也保留未覆盖说明。
统计显示总评论数、已有标签评论数、条目数及标签/情感内去重评论数。同一条评论可在同标签不同情境同时正负；不能跨标签或情感加总当作人数。中性不表示正负混合，空白不表示无问题。
机会、决策和助手的兼容问题组仅汇总负面主题，组内按评论去重；正面、中性保留在主题统计。旧纠错不修改新统计。新增模型单条打标按钮，仅主动点击调用；结果仍标待复核，可恢复初始标注。原商机比较、经济情景、权重、验证计划和JSON导出保留。
上传数据不套用同ID演示标注、不发送给云端模型；本地可按原文人工标注。新修正需原因，保存与数据替换会使旧对话结果失效。会话修正不持久保存，导出JSON增加主题版本、来源、条目及修正原因快照，旧纠错范围单独注明。

## 真实模型测试
使用现有本地配置DeepSeek v4.1 Flash / bailian-json-nonthinking，temperature=0，单条请求输出上限1600 token；只发送内置模拟评论与目录。沿用用户此前确认的免费额度及“用完即停”设置，无充值、无自动重试、无付费回退。控制台剩余额度与实际账单未独立查询，不把token消耗等同实际费用。
第一批首请求HTTP 400即停止，耗时515毫秒，未获usage；发现新打标提示词未明确写JSON，补充格式声明及Node回归后另起新批次，不隐去失败记录。
修正后对76条各调用一次，共76/76通过字段、枚举及原文连续片段校验；此为结构校验，不是语义准确率。与开发参考标注在“标签+情感集合”层面完全一致60/76，其中已确认50条为41/50，补查26条为19/26。该比较忽略片段边界与理由措辞，参考与目录参与过开发，不是独立测试集。
成功批次耗时中位数933.5毫秒，范围523–1441毫秒。prompt token 71385、completion token 4859、total token 76244；不包含首个400请求无法观测的用量。两批合计77次外部请求尝试，76次得到合格打标结构。结果没有自动覆盖用户已确认的本地参考标注。

## 分歧与判断
16条存在标签/情感集合分歧。r001/r002/r006增加内部结构标签可能有原文依据，应结合标注粒度复核，不能把所有增标一律当错标。
明确需要约束的例子：r068把“easy to fill”当补水频率正面、一般维护当清洗便利；r074把整体可靠/低成本推断成水泵寿命/滤芯支出；r075把整体steady推断成水泵稳定；r057因猫初期怕声音便推断噪声负面。r034/r043的中性与正负边界亦有分歧。逐字引用可以证明片段存在，不能证明推断正确。
因此目前适合“模型初标+原文审查+会话纠错”，不适合无人复核自动验收。保留已确认参考、允许人工修正/恢复，不以本轮结果宣布模型准确率或全面优于其他模型。19标签仍需后续针对材质、整体做工及操作便利性补充，未经定义与确认不随意扩目录。
