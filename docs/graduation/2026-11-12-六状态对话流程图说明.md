# 六状态对话流程图说明（含异常分支）

日期：2026年11月12日
图源文件：`figures/对话流程图-六状态-含异常分支.svg`（答辩用 PNG 同目录）
依据：《对话流程与验收清单》（2026-11-02）S1–S6 定义、A01–A12 异常用例
对应实现：`server/agent.mjs`（服务端校验与兜底）、`src/agent/contract.ts`（客户端镜像校验）、`src/agent/AgentWorkspace.tsx`（会话状态与 revision 失效机制）

## 一、图的读法

1. **纵向主干**：S1 确认范围 → S2 检查数据 → S3 识别偏好 → V 三重校验 → S4 核验风险 → S5 判断可解决性 → S6 条件性判断（三出口：继续研究 / 证据不足 / 暂缓+验证计划）。
2. **橙色虚线**：异常分支入口——S2 数据阻塞、V 校验不通过、S5 缺产品参数，各自进入拦截/追问环节后再回归主流程。
3. **暗金色实线**：回退与失效路径——修正导入回 S2、候选修正回 S3、参数补充回 S5。
4. **右侧长回环（A08）**：数据或标签中途变更时，旧解释全部失效（revision 绑定机制），流程回到 S2 重新检查，任何过期回答不允许以当前身份展示。

## 二、V 三重校验说明

V 是 S3→S4 之间唯一的通行关口，客户端与服务端双重执行：

| 校验 | 内容 | 失败行为 |
|---|---|---|
| 结构 | 回复必须是严格 JSON，仅含 answer/reviewIds（或 scopeNotice） | 422 拦截，不展示 |
| 引用 | 所有 reviewIds 必须存在于当前证据范围内 | 422 拦截，不展示 |
| 统计 | answer 禁用任何数字/编号；统计仅由确定性程序界面提供 | 422 拦截，不展示 |

引用存在性校验**不等于**语义支持校验——原文证据始终在界面可见，供人工抽查。

## 三、异常用例 ↔ 状态映射（A01–A12）

| 编号 | 场景 | 挂载状态 | 处理 |
|---|---|---|---|
| A01 | 空输入 | S1/S3 | 本地拦截，不发模型请求 |
| A02 | 无有效数据 | S2 | 引导导入或选择演示样本 |
| A03 | 模型密钥未配置 | 全局 | 显示模型不可用；规则分析继续可用 |
| A04 | 调用超时/失败 | 全局 | 明确失败类别，保留输入可重试；客户端 35s 中止、服务端 30s 上限 |
| A05 | 返回未知评论ID | V | 拒绝作为引用展示 |
| A06 | 数量与程序冲突 | V | 不采用模型数字 |
| A07 | 证据不足/矛盾 | S4 | 保留不确定或并列观点，不补造事实 |
| A08 | 中途替换数据/标签 | 全局 | 旧结果失效，回到 S2 重算（revision 机制） |
| A09 | 用户修改标签 | S3 | 先程序重算，再更新解释 |
| A10 | 评论正文含指令 | S5 | 作待分析数据，不执行指令 |
| A11 | 重复点击发送 | 全局 | 不并发重复提交 |
| A12 | 询问销量/进货建议 | S1/S6 | 范围说明拒绝经营预测 |

## 四、与实现的对应关系

- **A03**：`AgentWorkspace` capability 状态机（checking→ready/disabled/offline）
- **A04**：`AbortSignal.timeout(30000)`（服务端）+ 35s setTimeout（客户端）
- **A05/A06**：`validateReply`（服务端）+ `verifyReply`（客户端镜像）
- **A08**：revision = `crypto.randomUUID()`，绑定 dataset/corrections/aspectOverrides
- **A11**：`canSend` 门 + `active.current` 进行中锁
- **A12**：服务端正则拦截采购/进货措辞 + scopeNotice 固定回复通道
- **数据范围声明**：程序在回复通过校验后注入固定声明行，不依赖模型自觉

## 五、边界

本图为**设计文档**，描述目标行为与已实现机制的对应关系；六状态的**自主编排**（S1→S6 全自动流转）尚未实现，当前实现为"确定性六步页面 + 对话层"架构。此边界在答辩陈述时应如实说明。
