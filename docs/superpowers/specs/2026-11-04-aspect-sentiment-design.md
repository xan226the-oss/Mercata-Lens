# 主题情感接入设计
用户已于2026-11-04批准：多标签、逐标签正负中、去掉其他、保留原平台功能，继续实现展示统计与模型验证。起始HEAD d0462f6。
采用独立主题情感层，避免把正面反馈放入旧负面规则。替换旧规则本体会破坏基线；仅展示文件不能完成产品接入。主工作台默认新版，旧工作台保留切换入口。
目录引用r3的9组19标签。Annotation={topic,sentiment,evidence,reason}；证据必须是原文连续片段，允许同标签不同情境/情感，完全重复不重复计数。空标注是未覆盖/未标注状态，不是其他标签。
演示样本按原文全文匹配载入已确认50条，26条Codex补标独立注明未获用户确认，无法覆盖内容留待补充分组。上传数据不匹配演示ID，不出本机。会话纠错需原因，允许清空并可恢复初标。新旧纠错分开，新版更改使对话结果失效。
确定性汇总总评论数、已标评论数、条目数、各标签正负中评论数；同评论同标签同情感只算一次。下游商机/决策兼容映射只取负面主题，按评论去重，保留原有7个问题组及原文；明示新版主题统计依据。导出新增主题快照，注明旧规则修正的范围。
模型独立单评论打标接口，仅内置模拟数据，服务器按ID读取原文，不采信客户端原文。严格白名单目录、枚举情感、原文片段、长度/重复/数量约束。模型未配置、上传数据不云发、超额/失败无自动重试。对话协议额外接收新版会话修正，服务器重构基础标注并过滤到证据范围。
测试包括多标签正负并存、评论/条目去重、错误证据拒绝、同ID异原文不套用、上传隔离、人工修改和恢复、对话失效、导出快照、gateway验证。工程mock测试不消耗额度。实时测模型若调用则单独记录延时与token，不宣称独立准确率。
