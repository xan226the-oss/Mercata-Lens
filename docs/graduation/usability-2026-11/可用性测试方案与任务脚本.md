# Mercata Lens 目标用户可用性测试方案与任务脚本

版本：1.0 · 2026-11-12
依据：任务书承诺「招募不少于5位目标用户，记录任务完成率与SUS得分」；开题报告评测计划；C 方案交互规格
测试对象：Mercata Lens（商机镜）研究助手，内置模拟演示数据（demo 模式，无需配置模型即可测试规则功能；如测对话功能需网关与模型就绪）

---

## 1 测试目的与范围

检验目标用户（跨境电商新手卖家）能否在没有指导下完成"选题核验"核心闭环：

> 提出问题 → 查看证据原文 → 修正标签 → 得到条件性判断 → 导出研究记录

**测什么**：任务完成率、路径效率、理解度、SUS 量表评分
**不测什么**：模型回答的语义准确性（另由评测计划覆盖）、真实市场判断力、性能压测

## 2 参与者要求（≥5 人）

| 筛选项 | 要求 |
|---|---|
| 身份 | 有跨境电商选品经验或正在学习该流程者（同学中有相关实习/课程项目经历优先） |
| 屏蔽项 | 未参与本项目开发；过去一个月未深度使用本产品 |
| 数量 | 5–6 人（含 1 名备补） |
| 记录 | 每人一份数据表（见记录表模板），匿名编号 U1–U6 |

## 3 环境与准备

- 设备：测试者自用笔记本或实验室电脑，Chrome 浏览器，窗口 ≥1024px 宽
- 启动：`pnpm dev`（或 `npm run dev`）打开演示地址；**加载内置演示数据即可，无需登录**
- 若测对话任务：另开终端启动 `npm run agent:server`（需 `.env.local` 模型配置就绪；模型不可用时跳过 T3/T4，在记录表注明）
- 录屏（可选但强烈建议）：OBS 或 QuickTime 屏幕录制，仅录操作不录人脸
- 知情同意：开始前告知「产品使用模拟数据，测试约 20 分钟，过程可随时暂停」

## 4 任务脚本（5 项核心任务）

> 主持人念稿，观察者记录。**全程不给操作提示**；参与者卡住超 3 分钟记"需协助完成"。

### T1 熟悉与定位（预计 3 分钟）
**话术**：「这是一个帮你研究美国市场宠物饮水机选品的工具。请找到：目前数据里一共有多少条商品、多少条评论？数据是真实的还是演示的？」

- ✅ 通过标准：正确说出商品数/评论数，并指出"演示/模拟数据"标识（首页来源徽章）
- 观察点：是否注意到来源徽章与证据就绪状态

### T2 痛点核验（预计 5 分钟）
**话术**：「你想知道用户抱怨最多的问题。请进入痛点页面，找到一条关于『清洁困难』的评论，点开它的原文证据，告诉我：原文和你看到的人工/自动标签一致吗？」

- ✅ 通过标准：进入痛点页 → 定位清洁困难标签 → 打开原文抽屉 → 说出一致/不一致及理由
- 观察点：证据抽屉是否被自发使用；命中片段高亮是否被注意到

### T3 智能体提问与引用核验（预计 5 分钟，需模型就绪）
**话术**：「在研究助手页，向助手提问：『这批样本里有哪些清洗相关的问题？』等回答出现后，点击回答里的引用按钮，确认跳转到了对应评论原文。」

- ✅ 通过标准：成功发送问题 → 收到带引用的回答 → 点击引用定位到原文
- 观察点：输入被拒时的提示是否理解（空输入/网关未就绪）；对话与证据双栏切换（窄屏页签）是否顺畅

### T4 人工纠错与失效重算（预计 5 分钟，需模型就绪）
**话术**：「假设你认为某条评论的标签不对。请在证据区把它的某个主题标签改成中性，填写原因保存。然后观察：之前的助手回答有什么变化？」

- ✅ 通过标准：完成一次带原因的标签修正 → 察觉旧回答被标记过期/失效 → 理解需要重新提问
- 观察点：纠错原因必填是否造成困惑；"旧解释失效"提示是否被理解

### T5 条件性判断与导出（预计 4 分钟）
**话术**：「最后，请进入决策页面，查看系统给出的判断结论，并把本次研究记录下载保存到本地。」

- ✅ 通过标准：读出结论三态之一（继续研究/证据不足/暂缓）+ 指出验证计划存在 → 成功下载 JSON
- 观察点：结论措辞是否被正确理解（不会误读为"推荐进货"）；导出文件是否找到

## 5 流程与话术规范

1. **开场（2 分钟）**：「我们测试的是工具，不是你——遇到困难是测试发现，不是你的问题。请边操作边说出你在想什么。」
2. **中立记录**：只在任务间隔追问「刚才你在找什么？」；禁止说「你应该点这里」
3. **不干预原则**：提示仅当卡住超 3 分钟且参与者请求时给出，并在记录表标注"协助"
4. **收尾访谈（3 分钟）**：
   - 哪一步最让你困惑？
   - 「证据原文」对你判断问题有没有帮助？
   - 你会信任这个工具给的结论吗？为什么？

## 6 SUS 量表（测试后立即填写）

使用标准 10 题 SUS（5 分制，奇数题正面、偶数题反向），中文版题目：

1. 我愿意经常使用这个系统
2. 我觉得这个系统有不必要复杂性
3. 我觉得这个系统容易使用
4. 我需要技术人员支持才能使用
5. 我发现系统里各功能整合得很好
6. 我觉得系统里存在太多不一致
7. 大多数人能很快学会使用
8. 使用起来很别扭
9. 我使用时很有信心
10. 使用前我需要学很多东西

**计分**：每题得分 =（奇数题：分值−1）或（偶数题：5−分值），总分×2.5 → 每人 0–100 分；5 人取平均。**基准线：68 分为行业平均**。

## 7 指标定义

| 指标 | 定义 |
|---|---|
| 任务完成率 | 独立完成 / 全部尝试（需协助记半成功）÷ 每任务人数 |
| 完成用时 | 从任务话术念完到参与者自认完成的秒数 |
| 错误路径 | 每任务中走错页面的次数 |
| 协助次数 | 每任务中主持人给出提示的次数 |
| SUS | 第 6 节计分，保留一位小数 |

## 8 结果整理与呈现（测试后 3 天内）

1. 汇总表：每任务 × 每用户的完成状态/用时/错误/协助
2. SUS 均分 + 每题分布
3. 问题清单：按发生频率排序（≥3 人遇到 → P0；2 人 → P1；1 人 → 记录备查）
4. 归档位置：`docs/graduation/usability-2026-11/results/`（数据表 + 录屏索引）
5. 引用规范：论文与答辩中如实表述「N=5 模拟数据环境下的探索性可用性测试」，不夸大为真实市场验证

## 9 边界

- 测试使用内置模拟数据，反映**产品流程可用性**，不构成真实市场证据
- 对话任务依赖本地网关与模型配置；未配置时 T3/T4 缺测，SUS 仍有效（基于规则功能体验）
- 参与者为同学（非真实卖家）时，论文中如实标注参与者构成
