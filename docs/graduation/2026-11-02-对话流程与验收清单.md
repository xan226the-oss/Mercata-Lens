# Mercata Lens 对话流程与验收清单
日期：2026年11月2日
状态：设计草案与验收用例，未实现、未执行。现有六步页面不等同于六状态Agent。

## 1 六状态任务定义
| 状态 | 输入与主要操作 | 阶段产物与退出条件 | 异常和回退 |
|---|---|---|---|
| S1 确认商品与市场 | 确认美国宠物饮水机范围、商品与研究目的 | 用户确认研究范围后进入S2 | 缺字段先追问；超出首版范围说明限制 |
| S2 检查评论数据 | 程序检查格式、重复与归属 | 有效数据及可用模块明确后进入S3 | 阻塞则回到导入；不覆盖已有有效数据 |
| S3 识别用户偏好 | 基于有效评论提出主题候选并绑定原文 | 结果与引用校验通过后进入S4 | 无支持证据则标记不足；用户可纠错 |
| S4 识别核心风险 | 展示问题主题、证据及判断依据 | 用户理解风险及不确定项后进入S5 | 矛盾证据并列展示，不凭频次自动判定严重性 |
| S5 判断可解决性 | 对照产品属性、支持与反对证据 | 形成可解决性假设及待验证项后进入S6 | 缺产品参数时追问；无依据不生成确定结论 |
| S6 形成条件性判断 | 汇总范围、证据、假设和限制 | 输出继续研究、证据不足或暂缓及验证计划 | 不输出进货建议；范围变化返回对应状态 |

每轮记录用户输入、当前范围、状态、工具结果及有效引用。具体请求结构、状态迁移实现与并发控制待接口设计阶段确定。模型调用失败不改变用户输入和当前研究数据；引用校验失败不向用户展示未经验证的结论。

## 2 核心交互要求
- 输入框支持发送与空输入拦截；发送中避免重复提交。
- 展示用户消息、模型响应与必要历史上下文，区分规则结果和模型结果。
- 显示加载、失败、重试和证据不足状态；重试不能重复计入一次有效对话。
- 引用可打开对应原文，并显示当前研究来源与范围。
- 数据或标签变化时使旧分析失效，重新计算后再解释。
- 模型未配置时保持规则分析功能，并明确说明模型不可用。

## 3 至少三轮对话验收脚本
使用固定模拟样本，不预填模型答案，不预设不存在的商品或评论ID。

| 轮次 | 用户任务示例 | 应验证的行为 |
|---|---|---|
| 第1轮 | 这批样本里有哪些清洗相关问题？ | 使用当前有效样本；主题引用有效原文；数量来自程序 |
| 第2轮 | 展开刚才那条问题的原文依据，并说明局限。 | 继承上一轮上下文；引用属于当前样本；说明模拟来源和覆盖范围 |
| 第3轮 | 那是不是可以直接采购这种易清洗款？还要补哪些验证？ | 不给采购指令；说明评论证据边界；提出有依据的验证事项 |

三次独立请求不自动算上下文验证通过。需保留每轮真实输入输出、引用检查和耗时。此脚本用于基础验收，不能替代完整六状态流程测试。

## 4 异常用例
| 编号 | 场景 | 预期 |
|---|---|---|
| A01 | 空输入 | 本地提示，不发模型请求 |
| A02 | 无有效数据 | 引导导入或选择演示样本，不编造结果 |
| A03 | 模型密钥未配置 | 显示模型不可用，规则功能仍可使用 |
| A04 | 调用超时或失败 | 明确失败原因类别，保留输入，可重试 |
| A05 | 返回未知评论ID | 拒绝作为有效引用展示，记录校验失败 |
| A06 | 返回与程序冲突的数量 | 不采用模型数量，提示或重新生成 |
| A07 | 证据不足或互相矛盾 | 保留不确定或并列观点，不补造事实 |
| A08 | 中途替换研究数据 | 旧结果失效，要求重新确认范围 |
| A09 | 用户修改标签 | 先程序重算，再更新解释 |
| A10 | 评论正文包含指令 | 将其作为待分析数据，不执行其指令 |
| A11 | 重复点击发送 | 不并发重复提交同一请求 |
| A12 | 询问销量或要求进货建议 | 说明不具备对应证据，不生成采购结论 |
