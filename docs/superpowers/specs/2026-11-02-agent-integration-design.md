# Mercata Lens 智能体接入方案草案

日期：2026年11月2日
状态：方案待用户审阅，模型供应商与费用条件待确认；尚未实施。

## 目标与验收

面向智能体与大模型应用方向，在现有研究工作台上增加模型调用与多轮任务对话，验证至少三轮完整对话。保留免费规则分析流程，模型不可用时明确显示当前能力与失败原因。

## 路线比较

1. 云端模型API与本地接口服务：复用现有前端，服务端管理密钥与模型调用。作为优先细化的方案；供应商、网络可用性、费用与数据发送范围均待确认。
2. 本地模型与本地接口服务：适用于用户希望本地处理数据的情况；需先确认设备资源、可用模型与实际运行表现。
3. 暂时使用模拟响应：可用于开发交互与自动化测试，但不能作为模型接入或三轮真实对话验收成果。

## 拟采用的职责划分

- React工作台：保留现有六步研究流程，增加任务对话入口、输入、响应、历史记录、加载与失败反馈。
- 本地接口服务：读取本地安全配置，校验请求，管理会话，调用模型并校验返回结果；不引入登录与云数据库。
- 确定性程序：继续负责数据质量、范围、筛选、计数、规则与证据索引。服务端需校验引用是否属于当前样本，不能信任模型自行生成的评论ID或数字。
- 模型：基于明确的任务与证据解释结果、提出澄清问题和待验证事项，不输出进货建议。

六状态任务方案继续使用开题报告中的确认商品与市场、检查评论数据、识别用户偏好、识别核心风险、判断可解决性、形成条件性判断。实现前需为每一状态补齐输入、工具、阶段输出、退出与回退条件；不能把六个页面直接等同于已实现的Agent状态。

## 最小验证任务

固定研究范围与样本，以三轮连续对话验证：询问主要评论问题、追问原文依据、在证据不足或任务调整时要求澄清。记录实际请求、结果、耗时与是否成功，分别检查上下文、引用归属、统计一致性与越界输出。

异常场景至少覆盖空输入、无有效样本、证据不足、无效引用、模型调用失败、超时与重复提交。具体接口、错误结构与测试用例在实施计划中细化。

## 当前可推进的材料

1. 整理现有目录与运行步骤，编写工程架构和环境配置记录。
2. 补全对话节点、异常分支与验收用例。
3. 根据已有证据功能映射整理设计推导，标明待补调研与真实答辩反馈。
4. 模型确定后补技术选型确认书与调用记录。

## 需要用户提供的内容

- 模型API账号是否可用、服务商及费用上限；不通过聊天提供密钥。
- 开题答辩反馈已由用户于2026年11月2日转述为“继续往下做”，不再等待额外整改意见，不生成虚构反馈。
- 现有真实调研与草图若存于项目外，提供文件位置；后续真实用户访谈、互评及教师验收需由用户协调。

## 实施边界

仅使用模拟样本进行首轮技术验证。未获授权的数据不发送至云端。密钥不进入前端、版本库或日志；未获明确费用授权不产生付费调用。

本草案不覆盖抓取、Amazon接口、账号系统、云存储、部署与品类扩展。进入代码实施前审阅方案，再形成实施计划与当前任务单，并更新与新范围冲突的历史约束引用。
