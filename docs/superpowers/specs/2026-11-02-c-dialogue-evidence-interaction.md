# Mercata Lens 对话与证据双栏交互规格
日期：2026年11月2日
状态：用户已同意沿C方向细化；本规格为设计交付，未实现或用户验证。模型服务商、预算及真实调用仍待确认。

## 1 范围与结构
保留现有研究流程与规则模块。宽屏采用研究导航、任务对话、证据核验三个区域；“双栏”指对话与证据两个主要内容区。常驻范围条显示品类、市场、数据来源、数据版本与当前有效样本量，数量必须由程序读取。
首版不扩展品类，不引入抓取、登录、云存储或自动经营决策。视觉沿用现有浅灰蓝色变量，图中所有模型回答均为静态示意。

## 2 核心交互
| 区域 | 内容 | 操作与反馈 |
|---|---|---|
| 导航与阶段 | 当前研究步骤、已完成与待补状态 | 允许返回；未通过数据检查时不启动依赖分析 |
| 对话 | 用户消息、已校验解释、引用按钮、输入框 | 输入可编辑；空白不可发送；发送后显示处理状态，禁止重复提交 |
| 证据 | 引用ID、商品、星级、日期、来源、完整原文与命中片段 | 从引用定位评论；不改写原文；空选中时引导点击引用 |
| 人工纠错 | 原标签、修改后标签、原因 | 原因必填；提交前可取消；成功后重算并使依赖旧标签的解释失效 |
| 验证事项 | 条件性判断、缺失信息、待验证行动 | 用户可追问或暂停，不输出采购指令 |

## 3 状态转换
| 状态 | 输入与操作 | 展示与退出 |
|---|---|---|
| 未配置模型 | 可以查看规则结果；模型发送不可用 | 显示“对话暂不可用，可继续查看规则分析”，不能点击重试触发重复请求 |
| 就绪 | 有有效研究范围、数据与可用模型 | 输入非空后可发送，进入发送中 |
| 发送中 | 同一会话只允许一个在途请求 | 保留输入副本与会话版本，不先展示未校验答案 |
| 回答完成 | 结构、范围、引用与数字校验通过 | 显示答案及有效引用；可追问、核验或纠错 |
| 调用失败 | 连接或超时失败 | 保留用户输入与原有数据，允许重试；重试前复核模型配置和数据版本 |
| 引用不通过 | ID不存在、归属或版本不符 | 不展示未通过的答案；提示“结果未能核验，请重试或查看原始证据” |
| 证据不足 | 无足够支持信息 | 显示缺口与可补充项，允许结束；不伪装系统故障 |
| 旧解释失效 | 标签、范围或数据发生变化 | 旧消息可保留并标识，不再作为当前结论；重算后按需重新解释 |

若用户在请求途中更换数据或提交纠错，旧请求结果即使返回也不得覆盖当前研究。响应须绑定requestId、researchRevision及规则版本；这是拟实现的接口要求，不是现有能力。

## 4 引用与键盘操作
引用按钮带可理解的名称，如“查看评论r001”；点击后高亮当前引用，右侧显示同一评论。通过键盘触发时将焦点移入证据标题，提供“返回引用”操作。窄屏切换到证据页签时同步处理焦点。高亮需辅以文字或边框，不仅依赖颜色。
评论正文视为数据，不执行正文指令。统计由确定性程序返回，模型只能解释已经核实的数量与范围。跨样本评论或示例URL不得当作真实市场证据。

## 5 纠错与数据版本
1. 选定当前有效评论，展示原标签和可修改标签。
2. 填写修改与非空原因；无有效改动时不提交。
3. 提交前可取消；切换评论前提示处理未保存修改，不静默丢弃。
4. 应用后依据新标签计算主题、比较与判断；原文保持不变。
5. 标记受影响旧解释失效，提示“标签已修改，结果已重算；可重新解释”。
6. 生成新解释时绑定新版本；失败不恢复旧解释为有效状态。
纠错只在当前会话保留，刷新将丢失；未实现长期项目存储，不能在界面宣称已经永久保存。

## 6 响应式策略
宽屏显示两个主内容区；设计拟以1024px作为双栏切换起点，最终以可读宽度验证调整。更窄时使用“对话／证据”页签，研究导航收为入口，范围条保留来源与范围摘要。
窄屏点击引用切到证据，保留原文滚动和返回引用位置；切回对话时保留草稿、消息和当前阶段。首次进入证据页签无引用时显示选择提示。输入框不得遮住当前正文与错误反馈。用390px和900px及1440px视口验证，设计尺寸不代表已通过测试。

## 7 设计稿与验收对应
- 桌面正常态：固定范围、任务对话与引用到原文的对应。
- 纠错与重算：选中、编辑原因、应用、旧解释失效及重新解释。
- 失败与不足：配置缺失、超时、无效引用、证据不足分别反馈。
- 窄屏：页签切换、引用定位、草稿与返回位置保留。
用户任务验收：询问清洗问题→查看引用→追问边界→修改标签→确认新旧解释状态。真实模型三轮对话另行执行，静态设计稿不作为运行证据。

## 8 实施前待决事项
具体模型、费用授权、服务端运行方式与依赖选型待确认。当前可继续整理设计与实施任务，不发起付费调用、不上传用户数据。代码实现应复用现有ResearchContext、证据与纠错组件，增加独立会话契约与模型适配，避免把对话状态写入领域计算函数。
